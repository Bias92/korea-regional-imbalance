# 요구사항 명세

본 문서는 Korea Regional Imbalance Dashboard의 Phase별 요구사항을 정의한다.
요구사항은 기능 요구사항, 비기능 요구사항, 검증 기준으로 구분한다.

---

## 1. 사용자와 목표

### 주요 사용자

- 지역 불균형 문제를 빠르게 이해하려는 일반 사용자
- 소프트웨어공학 과제 평가자
- 프로젝트 진행 과정과 AI 활용 방식을 확인하려는 리뷰어

### 사용자 목표

- 수도권 집중과 지방 인구감소의 핵심 수치를 한 화면에서 파악한다.
- 시도별 인구 증감률 차이를 막대차트로 비교한다.
- 데이터 시각화 개발 과정에서 요구사항, 설계, 구현, 검증이 어떻게 연결되었는지 확인한다.

---

## 2. 요구사항 도출 및 관리 방식

본 프로젝트의 요구사항은 "일반 사용자가 지역 불균형을 빠르게 이해해야 한다"는 문제 정의에서
출발했다. 이후 과제 평가자가 확인해야 하는 프로세스 증빙 요구를 함께 반영했다.

| 단계 | 적용 내용 |
|---|---|
| 문제 정의 | 수도권 집중, 인구감소, 폐교 지표를 표가 아니라 시각화로 전달 |
| 사용자 분석 | 일반 사용자, 과제 평가자, 프로젝트 리뷰어를 주요 사용자로 정의 |
| 범위 결정 | Phase 1은 카드와 막대차트, Phase 2는 지도, Phase 3은 폐교 통계 확장 |
| 요구사항 명세 | 기능 요구사항과 비기능 요구사항으로 분리 |
| 수용 기준 | 각 요구사항에 완료 기준을 연결 |
| 추적성 | 요구사항을 데이터, 화면 코드, 테스트 계획에 매핑 |
| 변경 관리 | 새 기능은 요구사항 ID와 설계 결정 기록을 먼저 갱신한 뒤 구현 |

### 주요 유스케이스

| ID | 사용자 | 목표 | 기본 흐름 |
|---|---|---|---|
| UC-001 | 일반 사용자 | 핵심 통계를 한 화면에서 확인한다. | 대시보드 접속 → 통계 카드 확인 → 데이터 상태 확인 |
| UC-002 | 일반 사용자 | 시도별 인구 증감률을 비교한다. | 대시보드 접속 → 막대차트 확인 → 수도권과 비수도권 색상 비교 |
| UC-003 | 과제 평가자 | 개발 프로세스 적용 여부를 확인한다. | README 확인 → 프로세스 문서 확인 → 요구사항, 설계, 테스트 문서 추적 |
| UC-004 | 프로젝트 리뷰어 | AI 활용이 통제되었는지 확인한다. | AI 로그 확인 → 설계 결정 확인 → lessons learned 확인 |

## 3. Phase 1 범위

### 포함

- 수도권 인구 비중 카드
- 수도권 GRDP 비중 카드
- 인구감소지역 수 카드
- 폐교 수 카드
- 시도별 인구 증감률 막대차트
- 데이터 출처와 기준연도 표시

### 제외

- 시군구 단위 choropleth 지도
- 폐교 위치 기반 지도 레이어
- 실시간 API 연동
- 사용자 계정, 저장, 공유 기능

## 4. 기능 요구사항

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| FR-001 | 대시보드는 핵심 통계 카드를 표시해야 한다. | 인구, GRDP, 인구감소지역, 폐교 수 카드가 한 화면에 표시된다. |
| FR-002 | 대시보드는 시도별 인구 증감률을 막대차트로 표시해야 한다. | 17개 시도 데이터가 Chart.js 막대차트에 표시된다. |
| FR-003 | 수도권과 비수도권을 시각적으로 구분해야 한다. | 수도권 지역은 데이터와 차트에서 구분 가능한 스타일 또는 라벨을 가진다. |
| FR-004 | 데이터 기준연도와 출처 상태를 표시해야 한다. | 화면 하단 또는 설명 영역에 기준연도와 임시 데이터 여부가 표시된다. |
| FR-005 | 정적 JSON 데이터를 로드해야 한다. | `data/phase1-regions.json`을 기준으로 화면이 렌더링된다. |

## 5. Phase 2 기능 요구사항

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| FR-006 | 대시보드는 시도 단위 choropleth 지도를 표시해야 한다. | Leaflet 지도에 17개 시도 경계가 표시된다. |
| FR-007 | 지도 색상은 인구 증감률을 기준으로 구분해야 한다. | 감소·정체·증가 구간이 다른 색으로 표시된다. |
| FR-008 | 수도권은 지도에서도 구분되어야 한다. | 서울, 인천, 경기의 경계선이 다른 지역보다 강조된다. |
| FR-009 | 지도와 Phase 1 지표가 연결되어야 한다. | 지도 지역 선택 시 인구 증감률, 인구감소지역 수, 폐교 수가 표시된다. |
| FR-010 | 지도 경계 데이터 출처를 기록해야 한다. | `data/README.md`와 라이선스 파일에 출처가 남는다. |
| FR-011 | 지도 기준 지표를 전환할 수 있어야 한다. | 인구 증감률, 인구감소지역, 폐교 수 버튼으로 지도 색상 기준이 바뀐다. |
| FR-012 | 사용자가 특정 시도를 직접 선택할 수 있어야 한다. | 지역 선택 드롭다운에서 선택한 시도의 상세 정보가 표시된다. |

## 6. 비기능 요구사항

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| NFR-001 | 정적 호스팅 가능성 | 별도 빌드 없이 브라우저에서 실행된다. |
| NFR-002 | 반응형 레이아웃 | 데스크톱과 모바일 폭에서 주요 정보가 겹치지 않는다. |
| NFR-003 | 재현성 | 데이터 파일과 화면 코드가 Git에 함께 기록된다. |
| NFR-004 | 유지보수성 | 데이터, 화면 구조, 스타일이 분리되어 있다. |
| NFR-005 | 접근성 | 카드와 차트 주변 텍스트가 충분한 대비를 가진다. |
| NFR-006 | 지도 재현성 | 지도 경계 파일이 원격 호출이 아니라 저장소 데이터로 관리된다. |

## 8. 변경 관리

- 새 기능은 Phase 범위에 맞는 요구사항 ID를 먼저 추가한 뒤 구현한다.
- 지도, 폐교 위치 표시처럼 범위가 큰 기능은 Phase 1에 섞지 않는다.
- AI 제안으로 스코프가 바뀌면 `docs/design.md` 또는 `docs/ai-log/`에 결정 근거를 남긴다.
