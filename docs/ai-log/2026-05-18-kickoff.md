# 2026-05-18 프로젝트 킥오프 (Claude × Codex 교차 토의)

## 결정 사항

- **프로젝트명**: Korea Regional Imbalance Dashboard
- **기술 스택**: Vanilla HTML/CSS/JS + Chart.js + Leaflet
- **MVP 범위**: 통계 카드 + 막대차트 (지도는 Phase 2 목표)
- **AI 운용**: Claude(문서·토론) + Codex(구현·리뷰) 역할 분담

## 주제 선정 과정

### 1차 후보 (Claude 제안)

Claude는 초기 후보로 다음 3가지를 제안했다.

- 플래시카드 학습 앱
- 습관 트래커
- 가계부 앱

제안 근거: CRUD 구조가 명확해 요구사항 분석/QA 단계가 자연스럽게 드러난다.

### 반박 (Codex)

Codex는 위 후보들이 "과제 통과용으로는 무난하나 보고서가 뻔해진다"고 지적했다.

- 플래시카드는 요구사항이 자명해서 분석 단계의 lessons learned가 빈약
- 보고서에서 "왜 이 기능이 필요한가" 서술이 어려움

대안으로 **지역소멸 데이터 시각화 대시보드**를 제안.

- 본인의 기존 발표 주제(지역소멸)와 연결되어 도메인 지식 활용 가능
- 요구사항 분석이 실제로 의미 있음 ("사용자가 지역 차이를 어떻게 봐야 이해할까?")
- 데이터 시각화 특성상 자연스러운 스코프 확장/축소 의사결정 발생

### 최종 결정

Codex 안 채택. Claude도 동의하며 다음 리스크를 추가 지적했다.

1. 데이터 소싱 부담 (KOSIS, 행안부, 교육부 자료 형식 제각각)
2. 지도 시각화 난이도 (한국 GeoJSON, 행정구역 통합 이슈)
3. 스코프 크리프 위험

→ Phase별 마일스톤 + MVP 명시로 리스크 통제하기로 결정.

## 기술 스택 결정 근거

Codex가 정리한 vanilla 스택 채택 근거.

1. **경량성**: React/Next.js는 설정 오버헤드가 큼
2. **커밋 가시성**: 정적 파일 변경이 git history에 직관적으로 남음
3. **시각적 산출물**: Chart.js/Leaflet 결과물이 보고서 캡처에 적합
4. **AI 비교 용이성**: Claude(문서/UI 구조) vs Codex(구현/디버그) 역할 분담 명확
5. **탈출 경로**: 지도 막혀도 Chart.js만으로 MVP 제출 가능

## AI 도구 역할 분담

| 도구 | 담당 영역 |
|---|---|
| Claude | 요구사항 정리, 문서 작성, 의사결정 토론, 보고서 작성 |
| Codex | 코드 구현, 버그 수정, 비판적 리뷰, 커밋 메시지 정리 |

## Today's Lessons Learned

- **AI 두 개를 교차 사용하니 한쪽의 "무난한 답"이 걸러진다.** Claude의 1차 제안은 안전했지만 평범했고, Codex의 반박을 거치면서 과제 취지에 더 맞는 주제로 수렴했다.
- 단일 AI 사용 vs 교차 검증의 차이를 최종 보고서 본문에 비교 섹션으로 정리할 것.
- 프로세스 관점에서 "AI도 동료 리뷰가 필요하다"는 점이 첫 번째 lesson.
