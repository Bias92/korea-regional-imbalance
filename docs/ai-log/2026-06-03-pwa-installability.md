# 2026-06-03 PWA 설치성 추가 로그

## 배경

최종 점검 과정에서 산출물이 "앱인지 웹인지", 그리고 앱처럼 사용할 수 있는지에 대한 질문이 제기되었다.
현재 구현은 GitHub Pages에서 실행되는 정적 웹앱이므로 네이티브 iOS/Android 앱은 아니다.
다만 PWA를 적용하면 기존 웹 배포 구조를 유지하면서 사용자가 앱처럼 설치해 사용할 수 있다.

## 결정

네이티브 앱 패키징 대신 PWA 설치성을 추가했다.

- `manifest.webmanifest` 추가
- `service-worker.js` 추가
- 192px, 512px 앱 아이콘 추가
- `src/index.html`에 manifest, theme color, apple touch icon 연결
- `src/app.js`에서 service worker 등록
- 제출물 검증 스크립트에 PWA 파일과 아이콘 크기 검증 추가

## 판단 근거

- 과제 제출물은 웹 대시보드와 프로세스 증빙이 핵심이므로 네이티브 앱 패키징은 범위가 과하다.
- PWA는 정적 웹앱 구조와 GitHub Pages 배포를 유지하면서 "앱처럼 설치 가능"한 사용성을 제공한다.
- manifest와 service worker는 자동 검증 대상으로 넣을 수 있어 기존 품질 관리 흐름을 해치지 않는다.

## 교훈

웹앱과 네이티브 앱의 차이를 명확히 설명하는 것이 중요하다. "앱"이라는 표현을 사용할 때는
설치형 네이티브 앱인지, 브라우저 기반 PWA인지 구분해야 한다. 이번 변경은 기존 웹 산출물을
무리하게 네이티브 앱으로 포장하지 않고, PWA라는 현실적인 절충안으로 사용성을 높인 사례다.
