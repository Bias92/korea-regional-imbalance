# 최종 보고서 초안

본 문서는 소프트웨어공학 과제 제출용 보고서의 초안이다. 실제 제출본에서는 화면 캡처와
실행 결과 이미지를 추가하고, 문장 길이를 과제 분량에 맞게 조정한다.

---

## 1. 프로젝트 개요

### 주제

한국 지역 불균형을 설명하는 정적 웹 대시보드 개발.

### 문제 정의

수도권 집중, 지방 인구감소, 폐교 증가는 각각 따로 제공되는 통계로는 일반 사용자가 관계를
이해하기 어렵다. 본 프로젝트는 이 지표들을 하나의 화면에서 시각화하고, 위험지수와 비교 기능으로
해석을 돕는 것을 목표로 한다.

### 결과물

- 정적 웹 대시보드: `src/index.html`
- 데이터 파일: `data/phase1-regions.json`
- 자동 검증 스크립트: `tests/verify-data.mjs`, `tests/verify-ui-contract.mjs`
- 프로세스 증빙 문서: `docs/process.md`, `docs/requirements.md`, `docs/design.md`, `docs/test-plan.md`

---

## 2. 적용한 소프트웨어공학 방법론

### 방법론

본 프로젝트는 **위험 기반 반복·점진 개발**을 적용했다.

폭포수 모델처럼 모든 요구사항을 처음부터 고정하지 않고, MVP를 먼저 만든 뒤 위험도가 높은 기능을
단계적으로 추가했다. 동시에 V-Model식 추적성을 일부 적용하여 요구사항, 설계 결정, 테스트 항목을
서로 연결했다.

### Phase 구조

| Phase | 목표 | 결과 |
|---|---|---|
| Phase 1 | 통계 카드 + 막대차트 MVP | 완료 |
| Phase 2 | 시도 단위 지도 + 위험지수 분석 | 완료 |
| Phase 3 | 폐교 통계 + 필터 + 설명 카드 | 진행 중, 초안 구현 |
| QA / 보고서 | 검증, 캡처, 제출 문서 정리 | 진행 중 |

## 3. 요구사항 분석

주요 사용자는 지역 불균형 문제를 빠르게 이해하려는 일반 사용자, 과제 평가자, 프로젝트 리뷰어로
정의했다.

핵심 기능 요구사항은 다음과 같다.

- 핵심 통계 카드 표시
- 시도별 인구 증감률 차트 표시
- Leaflet 기반 시도 단위 지도 표시
- 지도 지표 전환
- 종합 위험지수 계산
- 위험지수 시나리오 전환
- 두 지역 직접 비교
- 지역 검색·필터·정렬
- 폐교 통계 전용 분석
- 데이터 신뢰도 상태 표시
- 보고서 요약 Markdown 내보내기

요구사항 상세와 추적성은 `docs/requirements.md`에 기록했다.

## 4. 설계 결정

### Vanilla HTML/CSS/JavaScript 채택

React나 Next.js 대신 Vanilla 스택을 사용했다. 이유는 다음과 같다.

- 정적 파일만으로 실행 가능
- Git 변경 이력이 단순함
- 과제의 핵심이 프레임워크 활용보다 프로세스 적용 증빙에 있음
- Chart.js와 Leaflet CDN만으로 필요한 시각화를 구현 가능

### 정적 JSON 데이터 채택

API 직접 호출 대신 `data/phase1-regions.json`을 사용했다. 브라우저 CORS, API 키, 외부 서비스 장애
위험을 줄이고, 제출 시점의 데이터를 Git에 고정하기 위한 결정이다.

### 위험지수 도입

단순 지도와 차트만으로는 사용자가 어느 지역을 우선 봐야 하는지 판단하기 어렵다. 따라서 인구 감소,
인구감소지역 수, 폐교 수를 결합해 0~100점 위험지수를 만들었다. 다만 이 지표는 정책 판단의
절대 기준이 아니라, 화면 탐색을 돕는 파생 지표로 정의했다.

## 5. 구현 결과

현재 앱에서 사용자가 수행할 수 있는 주요 동작은 다음과 같다.

- 핵심 통계 카드와 출처 확인
- 지도에서 위험지수, 인구 증감률, 인구감소지역, 폐교 수 지표 전환
- 지역 드롭다운으로 특정 시도 선택
- 위험지수 산식과 가중치 확인
- 위험지수 시나리오 전환
- 두 지역 직접 비교
- 지역명 검색, 수도권/비수도권 필터, 정렬
- 폐교 통계 필터와 전용 차트 확인
- 데이터 신뢰도 상태 확인
- 보고서 요약 Markdown 다운로드

## 6. 검증

자동 검증은 다음 명령으로 수행한다.

```bash
node --check src/app.js
node tests/verify-data.mjs
node tests/verify-ui-contract.mjs
python -m json.tool data/phase1-regions.json
python -m json.tool data/skorea-provinces-2018-topo-simple.json
```

검증 범위는 JavaScript 문법, JSON 구조, 지도 경계 매핑, 핵심 DOM id, 버튼 개수, 요구사항 추적성을
포함한다. 수동 검증 체크리스트는 `docs/test-plan.md`에 기록했다.

## 7. AI 보조 개발 운용

본 프로젝트는 Claude와 Codex를 역할 분담하여 사용했다.

| 도구 | 역할 |
|---|---|
| Claude | 요구사항 정리, 문서 초안, 보고서 구조 논의 |
| Codex | 코드 구현, 테스트 추가, 커밋 정리, 비판적 리뷰 |

AI 결과를 그대로 수용하지 않고, 요구사항·설계·테스트 문서에 연결해 추적 가능하게 남긴 점이 핵심이다.
날짜별 AI 활용 기록은 `docs/ai-log/`에 보관했다.

## 8. 한계와 향후 작업

현재 summary 요약 지표는 공식 통계로 교체했지만, regions 시도별 분석 값은 아직 화면 검증용
임시 데이터다. 따라서 지도 색상, 위험지수 순위, 폐교 전용 차트는 공식 시도별 데이터 교체 후
재검증해야 한다.

향후 작업은 다음 순서로 진행한다.

1. 시도별 인구 증감률 공식 데이터 교체
2. 시도별 폐교 수 공식 기준연도 확정
3. 위험지수 가중치와 등급 구간 재검토
4. 모바일 화면 캡처 및 QA
5. 최종 PDF 보고서 작성
6. GitHub Pages 배포

## 9. 결론 초안

프로세스 없이 바이브코딩을 진행하면 빠르게 화면은 만들 수 있지만, 데이터 신뢰도, 요구사항 추적,
검증 기준이 흐려질 수 있다. 본 프로젝트에서는 위험 기반 반복·점진 개발을 적용하여 MVP를 먼저
확보하고, 이후 지도, 위험지수, 비교, 폐교 분석, 데이터 신뢰도 표시를 단계적으로 추가했다.

그 결과 단순한 데이터 표시 화면에서 사용자가 기준을 바꾸고 지역을 비교하며 데이터 한계를 확인할 수
있는 분석형 대시보드로 발전했다. 특히 요구사항 ID, 설계 결정 기록, 테스트 계획, AI 작업 로그를
함께 관리한 점이 소프트웨어공학 프로세스 적용의 핵심 증빙이다.
